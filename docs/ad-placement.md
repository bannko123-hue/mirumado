## 1. 広告枠は4種類だけ

| 枠id | 置く位置 | 何を置くか |
|---|---|---|
| `slot-hero` | 記事冒頭（PR表記の直後、リード文の下、結論の直後） | **結論として最も勧めたい1件のみ。** 2件以上置かない |
| `slot-mid` | 本文中盤（そのサービスの解説を終えた直後） | **解説した当のサービス。** 文脈と一致しない案件を置かない |
| `slot-compare` | 比較表の直下 | 表に出したサービスのうち、**提携済みのものだけ** |
| `slot-footer` | 記事末尾（まとめの下） | 次に読ませる記事へのリンクと並べる。1〜2件 |

**数の上限: 1記事あたり2〜3枠。4枠以上置かない。**

**未提携の案件は、枠ごと置かずに公開する。** 「提携できていないから、代わりに別のサービスを勧める」という書き方をしない。読者にとって最良の答えと、自分が報酬を得られる案件が食い違うときは、**読者にとって最良の答えを書く。**

## 2. 仕組みと、いま置ける／置けないもの

### 2-1. `::ad{id=...}` が実際に出力するもの

`build.mjs` の `renderAdSlot()` の出力は、**`ad_slots` に `html:` があるかどうか**と、**`--drafts` を付けたかどうか**の2つで決まる。

#### (A) `html:` がある枠 — 本番でも `--drafts` でも、これが出る

```html
<!-- AD SLOT: slot-hero / ABEMAプレミアム（afb） -->
<aside class="ad-unit" id="slot-hero" data-ad-slot="slot-hero" aria-label="広告">
  <p class="ad-unit__label">広告</p>
  <div class="ad-unit__body"><!-- html: の値がここに、一字も変えずに入る --></div>
</aside>
<!-- /AD SLOT: slot-hero -->
```

- **`html:` の中身はエスケープされない。** `<a>` も計測用の `<img>` も、ASP からコピーしたそのままの形で出る。A8.net の禁止事項「広告素材の改変」に触れないための作りなので、**値を整形し直さないこと**（改行を1行に詰める以外は触らない）。
- `.ad-unit` は**細い実線枠＋薄い背景**の控えめな見た目。`.ad-unit__label` の「広告」だけが小さく付く。
- **「広告」ラベルは消さない。** ステマ規制と ASP の表記要件（`launch-checklist.md` #15）を満たすために必ず出す。

#### (B) `html:` が無い枠 — 本番ビルドでは**何も出ない**

```bash
node build.mjs          # → その枠は HTML に一切出力されない（コメントも残らない）
```

読者に「未挿入」の文言が見えることはない。**ページソースにも案件名は残らない**ので、提携状況が外から読めることもない。

#### (C) `html:` が無い枠 — `--drafts` のときだけ、目立つプレースホルダが出る

```html
<aside class="ad-slot" id="slot-hero" data-ad-slot="slot-hero">
  <p class="ad-slot__label"><span class="ad-slot__badge">広告枠</span><code>slot-hero</code></p>
  <p class="ad-slot__program">ABEMAプレミアム（afb）</p>
  <p class="ad-slot__note">差し込む位置: 記事冒頭、結論の直後</p>
  <p class="ad-slot__todo">ここにアフィリエイトタグを貼り付けてください（未挿入）</p>
</aside>
```

`assets/style.css` の `.ad-slot` は **3px の破線枠＋黄色背景**で、`.ad-slot__todo` には `▶` が付いて太字で出る。**これは執筆者が貼り忘れに気づくためのもの**で、`node build.mjs --drafts` でしか出ない。

> 枠の位置を目で確かめたいときは `node build.mjs --drafts && node serve.mjs` を使う。本番の見え方を確かめたいときは `--drafts` を付けずにビルドする。

### 2-2. アフィリエイトタグを貼る口は `ad_slots` の `html:` だけ

- 本文の Markdown は `renderInline()` で **HTML エスケープされる**。本文に `<a href="...">` と書いても `&lt;a href=...` という文字として表示されるだけで、リンクにならない。**この挙動は変わっていない。**
- 生 HTML を通せるのは **`ad_slots` の `html:` フィールドだけ**。ここだけがエスケープを通らない。
- したがって、**広告タグは必ずフロントマターの `html:` に置く。本文には `::ad{id=...}` の目印だけを書く。**

### 2-3. 「Markdown のリンク記法で貼ればいいのでは」——**やらない**

`[表示文字](https://px.a8.net/svt/ejp?a8mat=...)` と書けば、`build.mjs` は外部リンクとして `rel="nofollow noopener" target="_blank"` を付けて出力する。技術的には動く。

**それでもやらない理由**: A8.net の禁止事項に「**広告素材の改変**」がある（出典: https://www.a8.net/compliance/prohibited-matter.php ・2026-09-07 確認）。ASP が発行するリンクタグは、`<a>` に続けて 1×1 の計測用 `<img>` が付いている形が一般的で、そこから `href` だけを抜き出して貼り直す行為が「改変」に当たるかどうかを、**公開ページでは判断できない**。

→ **結論: タグは丸ごと `html:` に入れる。** `href` だけを抜き出す書き方は採らない。`html:` はエスケープされないので、抜き出す必要がそもそも無い。

### 2-4. したがって、当面の運用はこうする

| 時期 | 記事ファイルの書き方 |
|---|---|
| **提携が1件も通っていない今** | フロントマターに `ad_slots`（`html:` 無し）を書き、本文に `::ad{id=...}` を置いておいてよい。**本番ビルドでは何も出力されないので、公開しても読者には何も見えない。** |
| **提携が通ったら** | 該当する `ad_slots` の項目に `html:` を1行足すだけ。本文は触らない |

**以前は「提携が通るまで `ad_slots` も `::ad{}` も書かない」運用だった。** 未挿入のプレースホルダが読者に見えてしまうためと、`ad_slots` だけ定義すると毎回警告が出続けたため。**どちらも改修で解消したので、この制約は無くなった。**

- 未挿入の枠は本番ビルドで**何も出力しない**（§2-1 (B)）。
- 未挿入の枠は `--check` の**警告**として1箇所ずつ列挙される（§3-2 (c)）。エラーにはならないので、ビルドは通る。

なお、`ad_slots` に id を定義したのに本文に `::ad{}` が無い場合は、従来どおり別の警告が出る。**これは書き間違いのサインなので放置しない。**

```
  [警告] content/articles/xxx.md: ad_slots に "slot-footer" がありますが、本文に ::ad{id=slot-footer} がありません
```

## 3. 提携が通ってから、実際に貼るまでの手順

### 3-1. ASP の管理画面でリンクタグを取る（10分）

1. ASP にログイン → プログラム検索 → 該当プログラム → **提携申請**
2. 提携が承認されたら、そのプログラムの **広告リンク（素材）** を開く
3. **テキストリンクを選ぶ**（バナーは画像を読み込む。このサイトは外部画像を読み込まない設計なので使わない）
4. 表示されたタグを**一字一句そのままコピーする**。改行を含む場合は、あとで1行に詰める（`html:` は1行の文字列として読まれるため）
5. 同時に **単価・成果地点・却下条件・承認期間・リスティング可否・掲載NG媒体** をメモし、§5 の表の「要ログイン確認」を上書きする

### 3-2. 記事ファイルを編集する（1記事5分）

**(a) フロントマターの `ad_slots` に `html:` を足す**

枠そのものは既に書いてあるはずなので、**足すのは `html:` の1行だけ**。

```markdown
ad_slots:
  - id: slot-hero
    program: ABEMAプレミアム（afb）
    note: 記事冒頭、結論の直後
    html: '<a href="https://px.a8.net/svt/ejp?a8mat=XXXXXXXX" rel="nofollow">ABEMAプレミアムの公式サイトを見る</a><img border="0" width="1" height="1" src="https://www13.a8.net/0.gif" alt="">'
```

**`html:` の値の書き方（`build.mjs` のパーサ仕様）**

| 点 | 内容 |
|---|---|
| **1行に収める** | 値は「キー: 値」の1行。ASP のタグが複数行で表示されたら、**改行だけを消して1行にする**。それ以外は一字も変えない |
| **`'` で囲む** | HTMLタグには `"` が大量に入るので、**シングルクォートで囲む**。`"` で囲むと最初の `"` で切れる |
| **`#` はそのまま通る** | 値の途中の `#` はコメントにならない。`href="...#section"` のようなタグもそのまま書ける（2026-09-08 の改修で、値が `#` の手前で黙って切られるバグは直っている） |
| **`:` は大丈夫** | 値の中の `:`（`https://`）はそのまま通る |
| **`'` を含むタグ** | タグ自体に `'` が入っている場合はシングルクォートで囲めない。その1件はサイト担当に相談する（パーサがエスケープに未対応） |

> **`html:` の中身は一字も加工されずにそのまま HTML に出る。** 整形・改行の入れ直し・属性の並べ替えをしない。A8.net の「広告素材の改変」に当たり得る。

**(b) 本文の該当位置に枠を置く**（既に置いてあれば何もしない）

```markdown
（結論の段落）

::ad{id=slot-hero}

## 次の見出し
```

- **必ず行を独立させ、前後を空行で挟む。** 文中に書くとビルドが止まる。
- `id` は フロントマターの `ad_slots` の `id` と**完全一致**させる。違うとビルドが止まり、定義済みの id 一覧が表示される。

**(c) 確認する — `--check` の警告の読み方**

```bash
node build.mjs --check
```

まずサマリの行を見る。

```
  広告枠 57 箇所（うちタグ挿入済み 3 箇所）
```

（**これは3件貼ったあとの見え方の例。2026-09-15 時点の実際の出力は「広告枠 57 箇所（うちタグ挿入済み 0 箇所）」。**）

- 左の数（57）= 本文に置いた `::ad{}` の総数。**記事22本ぶんの実在の枠数と一致する。**
- **右の数（3）= そのうち `html:` が入っていて、実際に読者に出る枠の数。**
- **`html:` を足したのに右の数が増えていないなら、貼り方が間違っている。** よくある原因は、`html:` のインデントが `- id:` と揃っていない、`'` で囲み忘れて途中で切れている、の2つ。

次に、末尾の警告ブロックを見る。

```
検証 [警告] 広告タグ未挿入の枠が 54 箇所あります（エラーではありません）:
  - content/articles/j-league-live-streaming.md: 広告枠 "slot-mid"（ABEMAプレミアム（afb））に html が入っていません。本番ビルドでは何も出力されません
  ...
  → 提携が通ったら docs/ad-placement.md §3-2 の手順で ad_slots に html: を足してください。

検証: エラーはありません（警告 54 件）。
```

（同じく3件貼ったあとの例。**2026-09-15 時点の実際の出力は「未挿入の枠が 57 箇所」「警告 57 件」。**）

- **これは警告であってエラーではない。** ビルドは成功し、終了コードも 0 のまま。**この警告が残っていても公開してよい。**
- 意味は「この枠は本番ビルドで何も出力されない」だけ。読者には何も見えないので、害はない。
- **使い方**: 提携が通った案件を貼ったあと、この一覧に**その枠がまだ残っていないか**を見る。残っていれば貼れていない。
- 逆に、**貼ったつもりのない枠がこの一覧から消えていたら異常**。意図しない `html:` が入っていないか確認する。

最後に見た目を確認する。

```bash
node serve.mjs        # 該当記事を開き、リンクが実際に踏める形で出ているか目で見る
```

- 「広告」の小さいラベルが枠の上に出ているか。**出ていなければ公開しない**（表記要件を満たさない）。
- 黄色い破線の枠（`ここにアフィリエイトタグを貼り付けてください（未挿入）`）が**本番ビルドで出ていたら異常**。`--drafts` を付けたまま確認している可能性が高い。
- **リンクは自分で踏まない**（自己クリックは A8 の禁止事項）。踏んで確認したい場合は、申込画面まで進まない。

**(d) `updated` を上げるか**

広告を差し込んだだけで本文の事実が変わっていないなら、**`updated` は上げない**。読者には「その日に公式で確認した」と表示されるため（`daily-operation.md` §3-2）。

## 4. `build.mjs` の広告まわりの仕様（2026-09-08 改修・実装済み）

**この節はもともと「サイト担当への改修依頼」だった。改修は入ったので、以下は現在の仕様の記録。**

### 4-1. 入ったもの

| # | 内容 | 確認方法 |
|---|---|---|
| 1 | `ad_slots` の項目に **`html` フィールド**を書けるようにした。`renderAdSlot()` は `html` があればその文字列を**エスケープせずそのまま**出力する | §3-2 (a) の例で貼って、ページソースにタグがそのまま出ることを見る |
| 2 | **`html` が無い枠は、本番ビルドで何も出力しない。** HTML コメントも残さない | `node build.mjs` して、該当記事のソースに枠の痕跡が無いことを見る |
| 3 | `--drafts` のときだけ、従来の黄色いプレースホルダを出す | `node build.mjs --drafts` |
| 4 | **広告表記は消していない。** `html` を出すときも `<aside class="ad-unit">` と `<p class="ad-unit__label">広告</p>` が必ず付く | §3-2 (c) の目視 |
| 5 | サマリに **「広告枠 N 箇所（うちタグ挿入済み M 箇所）」** を出す | §3-2 (c) |
| 6 | `--check` で **`html` 未挿入の枠を警告として列挙**する。**エラーにはしない**（終了コード 0 のまま） | §3-2 (c) |

**あわせて直したパーサのバグ**: フロントマターの値で「半角スペース＋`#`」以降が、エラーも警告も無く切り捨てられていた。値の途中の `#` はコメントとみなさない実装に変えた。`title: Jリーグ 第1節 # 第2節の見方` は、この全体がタイトルになる。

### 4-2. CSS のクラスが2つに分かれた

| クラス | いつ出るか | 見た目 |
|---|---|---|
| `.ad-unit` | `html:` が入っている枠（**本番で読者が見るのはこれだけ**） | 細い実線枠＋薄い背景、小さく「広告」 |
| `.ad-slot` | `html:` が無い枠を `--drafts` でビルドしたとき | 3px 破線＋黄色背景（開発用） |

**`.ad-unit__label`（「広告」の表示）を CSS で消さないこと。** 表記要件を満たさなくなる。

### 4-3. まだ残っている制約

- **`html:` は1行の文字列しか読めない。** 複数行のタグは改行を消して1行にする（§3-2 (a)）。複数行を書けるようにするならパーサ側の対応が別途必要。
- **`'` を含むタグは書けない。** シングルクォートで囲む前提のため。該当するタグが出てきたらサイト担当に相談する。
- **`html:` の中身は検証されない。** URL が間違っていても、タグが壊れていても、ビルドは通る。**貼ったら必ず目で見る**（§3-2 (c)）。

## 5. 記事別の対応表（運用用マスター）

**読み方**

- **状態「未確認」** = そのASPにその案件があるかどうかを、公開ページでは確認できていない（＝3社すべて）。「ASP」欄は**当たりを付けた先**であって、確認済みの事実ではない。
- **状態「動線なし」** = 指定3ASPに該当案件が存在しない見込みのため、当面この枠に広告を置かない。

### 7-4. 弾かれた場合にどうするか

**申請して落ちても、作業のやり直しはほとんど発生しない。** だから**まず申請してみるのが正しい順序**。

2. **落ちた理由が明示的に「独自ドメインが必要」なら**、そこで初めてドメイン取得を検討する。**その時点なら傷は浅い**（提携ゼロなので、`handover.md` §4-4 の「公開後・提携が通る前」に当たる）。手順は §4-4 のとおりで、**`baseUrl` を1行変えるだけ**。
3. **1社だけ落ちた場合**、通った ASP の案件だけで始めてよい。`ad-map.md` の対応表は ASP をまたいで組んであるので、**通らなかった ASP の枠は空けたまま公開する**（§6「未提携だからという理由で、勧めるサービスを差し替えない」）。
4. **落選理由が書かれていないことも多い。** その場合は 1 を先に試す（記事を増やす）ほうが、ドメインを買うより安い。
