### 4-4. あとから独自ドメインに移すときの手順と、そのとき何が起きる（2026-09-14 追記）

**いま `mirumado.pages.dev` で公開しているのは、ドメインを買わないという運営判断による**（`launch-checklist.md` #2）。**あとから独自ドメインに移すことはできる。** ただし、移す時期が遅いほど失うものが増える。ここを読んでから決めること。

#### 結論を先に

- **技術的な差し替えは軽い。** `content/site.json` の `baseUrl` を1行変えるだけで、**canonical・OGP（`og:url`）・`sitemap.xml`・`robots.txt` の `Sitemap:` 行・`feed.xml`（RSS）・JSON-LD の `BreadcrumbList` の `item` が全ページぶん追随する。** 記事ファイルを1本も触らずに済む（§4-2）。内部リンクはもともとルート相対（`/soccer/...`）で書かれているので、ドメインが変わっても書き換え不要。
- **重いのは技術の外側。** 検索評価の引き継ぎ、ASP の提携の取り直し、Search Console のやり直し。**ここが本体。**

#### 手順（上から順に）

| # | やること | 所要 | 備考 |
|---|---|---|---|
| 1 | ドメインを取得する | 30分＋支払い | 旧 `launch-checklist.md` #2 の内容。更新料金（2年目以降）で比べること |
| 2 | Cloudflare にドメインを追加し、ネームサーバを向ける | 30分＋浸透待ち最大48時間 | Cloudflare Registrar で取ったなら不要 |

#### 何が起きるか（正直なところ）

**1. 検索評価は「リセット」に近いことが起きうる。ただし 301 でかなり減らせる。**

- 検索エンジンにとって `mirumado.pages.dev` と `example.com` は**別サイト**。ドメインを移すのは引っ越しであって、評価が自動で引き継がれるわけではない。
- **301 リダイレクトを全URLで1対1に張れば、多くは引き継がれる**というのが一般的な理解。ただし引き継ぎには時間がかかり（数週間〜数か月）、順位が一時的に落ちるのはよくある。
- **`.pages.dev` 固有の弱点がある。`pages.dev` は Public Suffix List に載っているため、`mirumado.pages.dev` は「`pages.dev` のサブドメイン」ではなく独立したサイトとして扱われる。** これは裏を返せば、他人の `*.pages.dev` の評判に巻き込まれないという利点でもある。**ただし「無料サブドメインだから検索で不利」という一般論の真偽は、公式情報では確認できていない。断定しない。**
- **早く移すほど傷は浅い。** 記事が22本・被リンクゼロの今なら、失うものはほぼ無い。**移す気があるなら、記事が増える前に決めるのが一番安い。**

**2. 301 で減らせる範囲と、減らせないもの**

| 減らせる | 減らせない |
|---|---|
| 旧URLを踏んだ読者を新URLへ運ぶ（**恒久的に**） | **ASP の登録URL**（リダイレクトは規約違反の判断材料にすらなる。必ず登録し直す） |
| クロール済みURLの評価の大部分 | **Search Console のデータ**（新プロパティに過去データは移らない。表示回数・クリックのグラフは切れる） |
| SNS等に貼られた旧URLの流入 | **アドレス変更ツール**。Search Console のアドレス変更ツールは**両方のプロパティの所有権**が要る。`pages.dev` 側は URLプレフィックスでしか確認できないため、**使えない可能性がある。使えなければ 301 と再クロール任せになる** |
| 旧サイトマップからの発見 | **ブックマーク・紙媒体に書いた旧URL**（301 が生きている限りは飛ぶ。Pages プロジェクトを消すと切れる） |

**3. Pages プロジェクトを消さないこと。**

`*.pages.dev` は**独自ドメインを追加したあとも、そのまま生き続ける**（＝自動では新ドメインに転送されない）。だから手順7の 301 を**自分で設定する**必要がある。

- Cloudflare 公式に **「Redirecting `*.pages.dev` to a Custom Domain」** という手引きのページが存在する（https://developers.cloudflare.com/pages/how-to/redirect-to-custom-domain/ ）。**この見出しのページがある事実自体が、「独自ドメインを足しても `pages.dev` は残って両方から見える」ことを示している**（残らないなら転送の手引きは要らない）。
- **ただし、この本文は読めていない**（2026-09-14 時点。作業環境から `developers.cloudflare.com` に接続できず、egress ポリシーで拒否された）。**設定手順は本人がこのURLを開いて確認すること。**
- 両方が生きたまま放置すると、**同じ内容が2つのURLで見える＝重複コンテンツ**になる。canonical は新ドメインを指すので致命傷にはならないが、**301 を張るのが正しい。**

**4. ASP の提携は取り直しになる前提でいること。**

- **登録外サイトへの広告掲載は明確な禁止行為**（`ad-placement.md` §6）。URL を変えたら、**貼ってあるリンクより先に、3社すべての登録サイトURLを直す。**
- 提携済みの案件が、URL変更で**自動的に引き継がれるとは限らない**。広告主によっては**再審査**になる。**審査中に旧URLで広告を出し続けてよいかは、各社の管理画面の表示に従う。**
- **したがって、移すなら「提携が通る前」が圧倒的に楽。** 提携が10件通ったあとにドメインを変えると、10件ぶんの確認作業が発生する。

| **公開後・提携が通る前 ← 2026-09-26 時点はここ** | **まだ安い。** Search Console の作り直しだけ（**#13 をまだ登録していないので、いまなら作り直しも発生しない**） |
| 提携が通ったあと | **ASP 3社の再申請が重い。** よほどの理由がなければ据え置く |
